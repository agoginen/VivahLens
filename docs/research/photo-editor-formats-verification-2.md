# Photo-editor formats verification (round 2)

Condensed from a research pass on **2026-11-22**: Adobe-owned docs and help pages, ExifTool's reverse-engineered tag table (pinned 13.64), RawTherapee source at tag **5.13** (`PPVERSION` 353) and darktable source at **release-5.6.2**. No editor was installed or run, so every behavioural statement comes from documentation or source. **UNVERIFIED** = not stated in a retrievable primary source.

## A. Adobe Camera Raw settings (`crs:`) in XMP sidecars

- Adobe documents only the **legacy** subset (Brightness, Contrast, Exposure, Shadows, Saturation, Sharpness, noise, vignette, Crop*, WhiteBalance, Temperature, Tint, ToneCurve). Every PV2012+ name and type below comes from **ExifTool** (reverse engineered, not Adobe), and the **ranges are UNVERIFIED** except where noted.
- Value syntax (Adobe XMP core types): Boolean `"True"`/`"False"`; Integer and Real are decimal strings with optional `+`/`-` (`+0.50` is legal).
- Names and types: `Exposure2012` real; `Contrast2012`, `Highlights2012`, `Shadows2012`, `Whites2012`, `Blacks2012`, `Clarity2012`, `Texture`, `Vibrance`, `Saturation` (−100…100) integer; `Dehaze` real; `WhiteBalance` string (`As Shot, Auto, Daylight, Cloudy, Shade, Tungsten, Fluorescent, Flash, Custom`), `Temperature` (2000…50000) and `Tint` (−150…150) integer; `SplitToningShadowHue/ShadowSaturation/HighlightHue/HighlightSaturation/Balance` integer; `LuminanceSmoothing`, `ColorNoiseReduction` (0…100); `Sharpness`, `SharpenRadius` (real); `GrainAmount/Size/Frequency` integer; `PostCropVignetteAmount/Midpoint/Feather/Roundness` integer plus `PostCropVignetteStyle` (1 highlight priority, 2 colour priority, 3 paint overlay); HSL `HueAdjustment*`, `SaturationAdjustment*`, `LuminanceAdjustment*` for Red/Orange/Yellow/Green/Aqua/Blue/Purple/Magenta.
- **Tone curve** is `ToneCurvePV2012`, a **child `rdf:Seq` element** (not an attribute) whose `rdf:li` items are text `"x, y"` on a 0…255 scale, plus `ToneCurveName2012` (`Linear, Medium Contrast, Strong Contrast, Custom`). Attribute-only XMP writers cannot express it.
- **Crop**: `HasCrop="True"` (exact string) with `CropTop/Left/Bottom/Right` as 0…1 fractions where Right and Bottom are **edge positions**, not insets (darktable reads them that way), `CropAngle` (sign convention UNVERIFIED), `CropConstrainToWarp`. There is **no aspect-ratio attribute**: aspect is implicit in the rectangle, so a crop needs the image size.
- **LUT**: no verified XMP representation for an applied LUT (`RGBTable`/`Table_<digest>` appear in no source read). Camera Raw's Apply LUT imports CUBE up to 64 divisions through its UI only.
- `ProcessVersion` string per process version is documented nowhere read (the repo's `"11.0"` is plausible, UNVERIFIED). Which of `Version`, `ProcessVersion`, `HasSettings` Lightroom requires is UNVERIFIED; keep writing all three.
- **Which files honour a sidecar**: Camera Raw help says a sidecar sits next to the raw file with the same base name and `.xmp`, and that **TIFF and JPEG settings are always stored in the file itself**; DNG settings live in the DNG unless sidecar mode is chosen. Lightroom Classic 15.0 also creates `.acr` sidecars for heavy edits; whether it honours a third-party `.xmp` when an `.acr` exists is UNVERIFIED (risk).
- **Re-read**: Lightroom does **not** silently apply a sidecar changed on disk. It shows "Metadata Was Changed Externally"; the photographer picks **Import Settings From Disk** or runs **Metadata > Read Metadata From File**. With "Automatically write changes into XMP", a dirty catalog entry can overwrite an external file.

## B. RawTherapee PP3 (5.13)

- A PP3 is a GLib key file: `[Group]`, `key=value`, case-sensitive, booleans lowercase `true`/`false`, `.` decimal separator, lists separated by `;`. **Partial files are normal**: only changed keys, no `[Version]`; `-p` files merge key by key; absent keys keep the neutral default. Sidecar name is `<image filename>.pp3`.
- Keys and GUI ranges: `[Exposure]` `Compensation` −5…12, `Brightness/Contrast/Saturation` −100…100, `Black` −16384…32768, `CurveMode` (Standard, FilmLike, …), `Curve`; `[White Balance]` `Enabled, Setting, Temperature` (1500…60000) `, Green` (a multiplier 0.02…100, not a ±150 tint), `Setting=Custom`; `[Vibrance]` `Enabled, Pastels, Saturated` ±100; `[Sharpening]` `Enabled, Method=usm, Radius` 0.3…3, **`Amount` 1…1000 (default 200)**; `[Directional Pyramid Denoising]` `Enabled, Luma, Chroma` 0…100 (**there is no `[Denoise]` section**); `[PCVignette]` `Enabled, Strength` −6…6, `Feather`, `Roundness` 0…100; `[Rotation]` `Degree` ±45; `[Shadows & Highlights]` `Enabled, Highlights, Shadows` 0…100 (one-sided), `HighlightTonalWidth` 10…100 (default 70), `ShadowTonalWidth` (default 30), `Radius` 1…100 (default 40); `[Dehaze]` `Enabled, Strength` 0…100; `[Local Contrast]` `Radius, Amount` 0…1; `[Crop]` `Enabled, X, Y, W, H` in **pixels** (inferred) so it needs the image size; `[Film Simulation]` takes **HaldCLUT**, not `.cube`.
- **Curves**: `type;x1;y1;x2;y2;…` with x,y in 0…1; types `Linear 0, Spline 1, Parametric 2, NURBS 3, CatmullRom 4`. Valid when exactly one `Linear` entry, or an odd count greater than 3. Example: `Curve=1;0;0;0.25;0.2;0.75;0.8;1;1;`.
- **Resize** works through the PP3 in the CLI: `[Resize] Enabled=true, AppliesTo=Full image, Method=Lanczos, DataSpecified=4 (long edge), LongEdge=<px>, AllowUpscaling=false`; `DataSpecified` 0 scale, 1 width, 2 height, 3 bounding box, 4 long edge, 5 short edge.
- **CLI**: `rawtherapee-cli -q -Y -o <out> -j<q> -js3 -b8 -p <recipe.pp3> [-p <more.pp3>] -c <files>` (`-c` last; pass `-js3` explicitly because the usage text and the code disagree; **do not pass `-w`**). `-p` files layer in order. Exit codes: 0 ok, −1 unknown option or usage, −2 load or process failure, −3 profile or option error, 1 stray argument, 2 no input; **a skipped output still exits 0**, so check that the output file exists. No concurrency option: parallelism means more processes (shared-config behaviour UNVERIFIED).

## C. darktable 5.6.2

- XMP: write `darktable:xmp_version="5"`, `iop_order_version="4"` (raw) and `auto_presets_applied="1"`. Each `darktable:history` item needs `operation`, `params` and `modversion`, else the whole history is discarded; `params` is the raw C struct as **lowercase hex** (or `gz`+base64). Wrong size drops the item, a newer `modversion` falls back to defaults, an older one is upgraded through `legacy_params`. Dropped modules do **not** change the exit code.
- `darktable-cli`: exit 0 or 1; injects `--library :memory:` and `--conf write_sidecar_files=never`; a positional XMP is applied to every input. `--style` needs a style already imported into `data.db` and cannot run in parallel on a shared config dir; `--apply-custom-presets 0` plus a positional XMP and a per-worker `--core --configdir` suits parallel runs. Sidecars are `<basename>.<ext>.xmp`.
- Struct versions at 5.6.2: exposure 7, temperature 4, colorbalancergb 5, colorbalance 3, filmicrgb 6, sigmoid 3, bilat 3, colorzones 5, vignette 4, grain 2, sharpen 1, crop 3, flip 2, lut3d 3.
- **Hand-encoding blobs is high risk**: no schema or checksum, per-release drift, white balance stored only as channel multipliers. Prefer the XMP route, restrict a first release to exposure, crop, flip, vignette, grain, bilat and sharpen, pin the darktable version, and golden-test every module against a real export before trusting it. There is no text parameter API.
