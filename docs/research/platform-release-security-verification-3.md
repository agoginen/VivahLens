## 1. OS secret storage from Node without native addons

### Answer

**Summary.** All three OS stores can be driven from a Node process by spawning a system tool, with the secret on the child's **stdin**, never on a command line: Windows = DPAPI (`ProtectedData`, CurrentUser) through Windows PowerShell 5.1 with the blob kept in a file; macOS = `/usr/bin/security -i` fed on stdin; Linux = `secret-tool store` fed on stdin. Two traps were found in sources/experiments: `cmdkey` silently stores an **empty** password when the password is piped, and `security find-generic-password -w` prints **hex** instead of the secret when any byte is non-printable. Headless Linux has no Secret Service, and `@napi-rs/keyring` then silently falls back to a **memory-only** kernel keyring.

**1.1 Windows**

| Option | Secret travels via | Result | Verdict |
|---|---|---|---|
| **DPAPI**: `[System.Security.Cryptography.ProtectedData]::Protect(bytes, entropy, CurrentUser)` in Windows PowerShell 5.1, blob stored by Node in a file | child **stdin** pipe → blob on stdout | [local run] round-trip equal (UTF-8 with non-ASCII); 278-byte blob for a ~60-byte secret; ~0.6 s per call; wrong entropy or one flipped byte ⇒ exit 1, `Exception calling "Unprotect"… The data is invalid.` (inside a `#< CLIXML` blob on stderr) | **Use** |
| Credential Manager via P/Invoke (`Add-Type` C# → `advapi32!CredWriteW/CredReadW/CredDeleteW`) | stdin | [local run] round-trip equal; 1.3-1.5 s per call (the C# is compiled each call); `cmdkey /list:<target>` then shows `Type: Generic`, `User:`, `Local machine persistence` (never the password); 2560-byte blob OK, **2561 bytes fails** (`The stub received bad data`) | OK, if entries must be visible in the Credential Manager UI or shared with Rust `keyring`; slower |
| `cmdkey /generic:<T> /user:<U> /pass:<P>` | **command line** | works, prints `CMDKEY: Credential added successfully.` | **Never for secrets**: the password is a process argument (Analysis (not from a source): any same-user process can read command lines; see the `ps` point in 1.2) |
| `cmdkey /generic:<T> /user:<U>` (docs: "If `<password>` isn't supplied, it will be requested") with the password piped on stdin, CRLF, LF and unterminated | n/a | **[local run] exit 0 and "Credential added successfully", but reading the entry back with `CredReadW` shows `CredentialBlobSize = 0`: an EMPTY password was stored** (it prompts on the console, not on stdin) | **Never** (silent failure) |
| `Windows.Security.Credentials.PasswordVault` (WinRT, from PS 5.1) | stdin | [local run] round-trip OK but **5.5 s** per call | not worth it |

- **Scope semantics (docs).** `DataProtectionScope.CurrentUser`: "The protected data is associated with the current user. Only threads running under the current user context can unprotect the data." `LocalMachine`: "Any process running on the computer can unprotect data." `Protect(Byte[] userData, Byte[] optionalEntropy, DataProtectionScope scope)`; on .NET Core/.NET 5+ "Calls to the Protect method are supported on Windows operating systems only" (`PlatformNotSupportedException` elsewhere). Windows PowerShell 5.1 runs on .NET Framework, where the class lives in `System.Security.dll` → `Add-Type -AssemblyName System.Security` first (works [local run]). `pwsh` 7 was not installed here: **UNVERIFIED** whether `ProtectedData` loads there without an extra assembly.
- *Analysis (not from a source):* DPAPI (CurrentUser) gives **no per-application isolation**: any process running as the same user can call `Unprotect`. `optionalEntropy` binds a blob to a purpose (a blob copied to another `service/account` name failed to decrypt [local run]) but is not a secret. It protects against other users, offline disk theft and backups, not against malware in the user's session.
- **Credential Manager facts (docs).** `CREDENTIAL.CredentialBlobSize` "cannot be larger than `CRED_MAX_CREDENTIAL_BLOB_SIZE` (5*512) bytes" (= 2560, matches the [local run] failure at 2561); `CredWrite` "creates a new credential or modifies an existing credential… If a credential with the specified TargetName and Type exists, the new specified credential replaces the existing one"; `CRED_PERSIST_LOCAL_MACHINE` "persists for all subsequent logon sessions on this same computer. It is visible to other logon sessions of this same user on this same computer"; `cmdkey` syntax `cmdkey {/add:<targetname>|/generic:<targetname>} /user:<username> [/pass:<password>]`, `/list[:<targetname>]`, `/delete:<targetname>`, and "Passwords are not displayed after they're stored" (so `cmdkey` cannot read a secret back; [local run] `cmdkey` creates `persist=3` (ENTERPRISE) entries, my P/Invoke used `2` (LOCAL_MACHINE)).

Tested script pair (static text, passed with `-EncodedCommand`, so nothing secret is on the command line; secret in = stdin bytes, blob out = stdout bytes; the entropy `vivahlens:v1:<service>:<account>` goes in env var `VL_ENTROPY`):
```powershell
$ErrorActionPreference='Stop'; $ProgressPreference='SilentlyContinue'
Add-Type -AssemblyName System.Security
$ms = New-Object System.IO.MemoryStream; [Console]::OpenStandardInput().CopyTo($ms); $in = $ms.ToArray()   # raw bytes: no console-encoding surprises
$entropy = [System.Text.Encoding]::UTF8.GetBytes($env:VL_ENTROPY); $scope = [System.Security.Cryptography.DataProtectionScope]::CurrentUser
function Out-Bytes([byte[]]$b) { $o = [Console]::OpenStandardOutput(); $o.Write($b, 0, $b.Length); $o.Flush() }
Out-Bytes ([System.Security.Cryptography.ProtectedData]::Protect($in, $entropy, $scope))      # decrypt: ...::Unprotect(...)
```
Node side: `spawn('%SystemRoot%\\System32\\WindowsPowerShell\\v1.0\\powershell.exe', ['-NoProfile','-NonInteractive','-ExecutionPolicy','Bypass','-EncodedCommand', Buffer.from(script,'utf16le').toString('base64')], {shell:false, windowsHide:true})`, then `child.stdin.end(secretBytes)`. Use the absolute path (no PATH lookup) and keep the script a constant.

- **`ps` visibility.** With `-w <password>` the secret is in `argv`. Apple's help string calls this "insecure" (`[APL security.c#L267]`); *Analysis (not from a source):* `argv` is readable by other processes (macOS `ps -ww`), which is why the stdin route through `security -i` is the one to use. **UNVERIFIED by execution** that the stdin route keeps `ps` clean (it cannot appear in `argv` by construction: the process is started as `security -i`).
- **Access control and prompts.** "By default, the application which creates an item is trusted to access its data without warning. You can remove this default access by explicitly specifying an empty app pathname: `-T ""`"; `-A` = "Allow any application to access this item without warning (insecure, not recommended!)"; `-T` = trusted app, repeatable `[APL security.c#L260-L265]`. Newer macOS adds per-item **partition lists**: `security set-generic-password-partition-list -S <comma-separated partition IDs> [-k keychain-password]` `[APL security.c#L334-L348]`. *Analysis (not from a source):* an item created through `/usr/bin/security` is trusted for `security` itself, so **any same-user process that can run `security find-generic-password -w` reads it with no prompt** while the keychain is unlocked; and an item created by the CLI, when later read by our signed Tauri/Rust app through the Keychain API, may raise an "allow access" prompt. Pick **one** reader/writer per platform (see 1.5).

**1.3 Linux: `secret-tool` (libsecret)** (source read; **not executed**, no Linux machine)
- `secret-tool store --label='<label>' <attr> <value> [<attr> <value> …]`; `lookup <attr> <value> …`; `clear <attr> <value> …`; `search [--all] [--unlock] …`; `lock [--collection=…]` `[LSEC tool/secret-tool.c#L76-L83]`.
- **Store reads the secret from stdin.** If stdin is a tty it prompts (`getpass("Password: ")`), otherwise it reads **until EOF**: `[LSEC tool/secret-tool.c#L345-L348]`. Limit: the buffer is `remaining = 8192` bytes (a longer secret prints "password is too long" and is cut) `[LSEC tool/secret-tool.c#L265-L293]`; the data must be valid UTF-8, else `password not valid UTF-8` and exit 1 `[LSEC tool/secret-tool.c#L296-L302]`. **A trailing newline is stored as part of the secret** (man page: "If you provide a newline via stdin it will be stored as part of the password") `[LSEC docs/man/secret-tool.xml#L78-L83]`, so never `echo secret |`; write the bytes with no newline. Storing with the same attributes **updates** the item `[LSEC docs/man/secret-tool.xml#L73-L76]`.
- **Lookup** writes the secret to stdout, adding a newline only if stdout is a tty `[LSEC tool/secret-tool.c#L211-L224]`; "first password that is already unlocked will be returned. If necessary an item will be unlocked" (can raise an unlock prompt) `[LSEC docs/man/secret-tool.xml#L98-L103]`. **Not found = exit 1 with nothing on stderr** (`if (value == NULL) return 1;`) `[LSEC tool/secret-tool.c#L257-L258]`; **errors = exit 1 with `secret-tool: <message>` on stderr** `[LSEC tool/secret-tool.c#L251-L255]`. So "absent" and "backend broken" are both exit 1 and are told apart only by stderr being empty or not. Secrets that are not `text/plain` (or `application/octet-stream` valid UTF-8) are refused: "secret does not contain a textual password" `[LSEC tool/secret-tool.c#L98-L103]`, `[LSEC tool/secret-tool.c#L214-L217]`.
- **Clear**: "All unlocked items that match the attributes will be removed" `[LSEC docs/man/secret-tool.xml#L114-L115]`; exit 0 on success, otherwise exit 1 (silent when nothing matched, message on error) `[LSEC tool/secret-tool.c#L172-L184]`. Exit status doc: "On success 0 is returned, a non-zero failure code otherwise" `[LSEC docs/man/secret-tool.xml#L152-L154]`; usage errors exit 2 `[LSEC tool/secret-tool.c#L76-L83]`.
- Attributes are ordinary arguments (visible in `ps`): use non-secret names only (`service`, `account`).
- **What it needs.** A Secret Service provider on the user's **session** D-Bus: the spec describes "a service running in the user's login session" (https://specifications.freedesktop.org/secret-service-spec/latest/description.html); `gnome-keyring-daemon` "implements the DBus Secret Service API, and you can use tools like seahorse or secret-tool to interact with it" (gnome-keyring 42.1 man page); KeePassXC and KWallet can also provide it (per the `@napi-rs/keyring` README list below).
- **Headless** (SSH session without `DBUS_SESSION_BUS_ADDRESS`, containers, CI, WSL without a user session): no provider ⇒ `secret-tool` exits non-zero with a D-Bus error on stderr; the exact message is **UNVERIFIED** (not reproducible here), hence the design below keys on "exit 1 + non-empty stderr ⇒ unavailable". Ways to get a keyring headless: `gnome-keyring-daemon --unlock` "Read a password from stdin, and use it to unlock the login keyring or create it if the login keyring does not exist" and `--login` "reads all of stdin (including any newlines) as a login password" (man page), i.e. someone must supply a keyring password non-interactively, which defeats the purpose on a server. *Analysis (not from a source):* for headless use, **do not persist secrets by default**: accept them per-invocation (env var / stdin), or require an explicit `--insecure-file-store` opt-in that writes a `0600` file (Topic 2) and prints a warning.

**1.5 Recommended minimal design**

*Analysis (not from a source); the code below was exercised [local run]: 5 `node --test` cases passed on Node 24.19.0 using type stripping (no build step), incl. a real DPAPI round-trip, a wrong-entropy rejection, and macOS/Linux command-shape assertions through the fake runner.*

- **One owner per secret.** If the Tauri shell (Rust `keyring`) is the only process that holds API keys/refresh tokens, the Node agent gets them over IPC/env per run and needs **no** store. If the Node CLI must persist secrets itself (today it does: `license.json` holds a `refreshToken`), use the Node store below, and do not let the Rust side read the same secrets with a different library (macOS ACL prompts; Windows format mismatch: DPAPI file vs Credential Manager).
- **Interface + runner seam** (all child-process use behind `Runner`; `shell:false`; secrets only in `opts.stdin`; tests inject a fake):
```ts
export type RunOpts = { stdin?: Uint8Array | string; timeoutMs?: number; env?: Record<string, string> };
export type RunResult = { code: number | null; stdout: Buffer; stderr: string; timedOut: boolean };
export type Runner = (cmd: string, args: readonly string[], opts?: RunOpts) => Promise<RunResult>;
export interface SecretStore {
  readonly backend: string;                                            // 'windows-dpapi' | 'macos-keychain' | 'secret-service'
  get(service: string, account: string): Promise<string | undefined>;  // undefined = absent; throws SecretStoreError('unavailable'|'corrupt'|'failed'|'invalid-name')
  set(service: string, account: string, secret: string): Promise<void>;
  delete(service: string, account: string): Promise<boolean>;
}
const NAME = /^[A-Za-z0-9][A-Za-z0-9._-]{0,63}$/;                     // service/account: also safe inside `security -i` lines and file names
const enc = (s: string) => 'v1:' + Buffer.from(s, 'utf8').toString('base64');   // printable-ASCII envelope on EVERY backend
```
  The envelope matters: it keeps `security find-generic-password -w` from switching to hex output, keeps `secret-tool` input valid UTF-8 and under 8192 bytes, and makes a store/read mismatch detectable (`v1:` prefix).
- **macOS store:** `set` → `run('/usr/bin/security', ['-i'], { stdin: 'add-generic-password -U -a ' + account + ' -s ' + service + ' -l ' + service + ' -X ' + hex(enc(secret)) + '\n' })`; `get` → `['find-generic-password','-a',account,'-s',service,'-w']`, exit 44 ⇒ `undefined`, strip one trailing `\n`, decode; `delete` → `['delete-generic-password','-a',account,'-s',service]`, exit 44 ⇒ `false`.
- **Linux store:** `set` → `run('secret-tool', ['store','--label','VivahLens ' + service + '/' + account,'service',service,'account',account], { stdin: enc(secret) })`; `get` → `lookup service S account A`: exit 0 ⇒ decode; **exit 1 and empty stderr ⇒ `undefined`**; exit 1 with stderr, timeout, or `ENOENT` ⇒ `SecretStoreError('unavailable')`; `delete` → `clear …` with the same mapping. Use a 15 s timeout (an unlock prompt can block).
- **Windows store:** blob in `%LOCALAPPDATA%\VivahLens\secrets\<service>.<account>.dpapi`, written to a temp name with `flag:'wx'` then `rename` (atomic replace); `xform()` runs the script above with `VL_ENTROPY`; an `Unprotect` failure containing "The data is invalid" ⇒ `SecretStoreError('corrupt')` (different Windows user/profile, tampering, wrong purpose).
- **Selection:** `createSecretStore(process.platform, nodeRunner, dataDir)`; on Linux probe once with `lookup service vivahlens account __probe__` (exit 1 + empty stderr = backend OK; anything else = unavailable) and then fall back to **"no persistence"** unless `--insecure-file-store` was given.
- **Fake runner for tests** (records every call so a test can assert no secret reaches `args`):
```ts
export type Script = Array<{ when: (cmd: string, args: readonly string[], opts: RunOpts) => boolean; reply: Partial<RunResult> }>;
export function fakeRunner(script: Script) {
  const calls: Array<{ cmd: string; args: readonly string[]; opts: RunOpts }> = [];
  const run: Runner = async (cmd, args, opts = {}) => {
    calls.push({ cmd, args, opts });
    const hit = script.find((s) => s.when(cmd, args, opts));
    if (!hit) throw new Error(`unscripted call: ${cmd} ${args.join(' ')}`);
    return { code: 0, stdout: Buffer.alloc(0), stderr: '', timedOut: false, ...hit.reply };
  };
  return { run, calls };
}
// e.g. Linux "absent": fakeRunner([{ when: (_c, a) => a[0] === 'lookup', reply: { code: 1 } }])
//      Linux "no daemon": reply: { code: 1, stderr: 'secret-tool: <D-Bus error>' }   -> SecretStoreError('unavailable')
//      macOS "absent": reply: { code: 44 }
```
  Real-OS integration tests (Windows DPAPI round-trip; a macOS/Linux CI job that does set/get/delete of a throw-away `vivahlens-test` service) stay separate and are skipped when the tool is missing.

## 2. Restricting a token/secret file to the current user

### Answer

**Summary.** POSIX: create the file **atomically** with `open(path, 'wx', 0o600)`; the mode is applied only at creation, is ANDed with the umask, and `wx` refuses an existing path or symlink. Windows: `mode` and `fs.chmod` do **not** touch the ACL (they only flip the read-only attribute); restrict with `icacls <file> /inheritance:r /grant:r *<SID>:F` (~65 ms), taking the SID from `whoami /user /fo csv /nh`, and verify from the SDDL. A Windows file is born with the parent's inherited ACL, so close the create-then-restrict race by (a) restricting the **directory once** (new files inherit only the user's ACE), or (b) creating the file **empty**, restricting + verifying, and only then writing the secret, or (c) creating it with its DACL in one call via .NET `FileStream(…, FileSecurity)` from PowerShell (~0.5 s).

**2.1 POSIX (docs; this machine is Windows, so the POSIX rows are from specs, not executed)**
| Fact | Source |
|---|---|
| `fs.open(path[, flags[, mode]])`: "`mode` sets the file mode (permission and sticky bits), but only if the file was created"; `fs.writeFile` `mode` default `0o666`, `flag` default `'w'` | `[N24 fs.md#L4052-L4054]`, `[N24 fs.md#L5683-L5684]` |
| Flag `'wx'`: "Like `'w'` but fails if the path exists" | `[N24 fs.md#L9268]` |
| Created mode = requested mode AND NOT umask: "a bitwise AND is performed on the file-mode bits and the corresponding bits in the complement of the process' file mode creation mask… all bits in the file mode whose corresponding bit in the file mode creation mask is set are cleared". So `0o600` can only become more restrictive (e.g. umask `0o277` → `0o400`), never looser | POSIX `open()`, https://pubs.opengroup.org/onlinepubs/9799919799/functions/open.html |
| `O_CREAT\|O_EXCL`: "open() shall fail if the file exists. The check for the existence of the file and the creation of the file if it does not exist shall be atomic with respect to other threads"; a symbolic link at the path ⇒ fails with `EEXIST` "regardless of the contents of the symbolic link" | same POSIX page |
| Do not "fix" modes with `process.umask()`: calling it **with no argument** is deprecated (Stability 0) because it "causes the process-wide umask to be written twice. This introduces a race condition between threads, and is a potential security vulnerability"; `umask(mask)` throws inside `Worker` threads | `[N24 process.md#L4401-L4404]`, `[N24 process.md#L4440]` |
| `fs.mkdir` option `mode`: default `0o777`, "**Not supported on Windows**" | `[N24 fs.md#L3876-L3877]` |
| Per-user runtime directory for handshake/socket files (`XDG_RUNTIME_DIR`): "The directory MUST be owned by the user, and they MUST be the only one having read and write access to it. Its Unix access mode MUST be 0700" | https://specifications.freedesktop.org/basedir/latest/ |

**2.2 What `mode` and `fs.chmod` do on Windows** (docs, then **[local run]** on NTFS)
- Docs: "Caveats: on Windows only the write permission can be changed, and the distinction among the permissions of group, owner, or others is not implemented" `[N24 fs.md#L2744-L2746]`; `fs.open`: "On Windows, only the write permission can be manipulated" `[N24 fs.md#L4052-L4054]`; "On Windows, only `S_IRUSR` and `S_IWUSR` are available" `[N24 fs.md#L8903]`.
- [local run] `writeFileSync(f, …, { mode: 0o600 })` ⇒ `stat.mode = 0o100666`, and `icacls` shows the **inherited** ACL (`NT AUTHORITY\SYSTEM:(I)(F)`, `BUILTIN\Administrators:(I)(F)`, `DOMAIN\user:(I)(F)`): the mode is ignored. `chmodSync(f, 0o400)` ⇒ `stat.mode = 0o100444`, `attrib` shows `R`, later writes fail with `EPERM`, **ACL unchanged**; `chmodSync(f, 0o600)` ⇒ `0o100666` again. So a "0600" test or call on Windows proves nothing: the repo's `LicenseStore` (`packages/cli/src/licenseClient.ts:39-41`) and handshake file (`packages/cli/src/commands.ts:264`) rely on exactly this.

**2.3 `icacls`: exact commands**
- Syntax (docs): `icacls name [/grant[:r] Sid:perm[...]] [/inheritance:e|d|r] [/save aclfile] [/Q]`. "SIDs may be in either numerical or friendly name form. If you use a numerical form, affix the wildcard character `*` to the beginning of the SID." `/grant:r` "Permissions replace previously granted explicit permissions. Not adding :r means that permissions are added…". Simple rights: `F` full, `M` modify, `RX`, `R`, `W`, `D`, `N`; inheritance flags `(OI)` object inherit, `(CI)` container inherit, `(NP)` don't propagate, `(IO)` inherit only (directories). https://learn.microsoft.com/en-us/windows-server/administration/windows-commands/icacls. **Docs discrepancy:** the Learn page lists the parameter as `/inheritancelevel:e|d|r`, while the tool's own `icacls /?` prints `/inheritance:e|d|r` ([local run]; `/inheritance:r` works).
- **Restrict a file** (one invocation; `r` = remove inherited ACEs, `/grant:r` = explicit ACE for exactly one principal):
  `icacls "<file>" /inheritance:r /grant:r "*<SID>:F" /Q`  ⇒ [local run] `<file> DOMAIN\user:(F)`, SDDL `D:PAI(A;;FA;;;S-1-12-1-…)` (`P` = `SE_DACL_PROTECTED`, `AI` = `SE_DACL_AUTO_INHERITED`: https://learn.microsoft.com/en-us/windows/win32/secauthz/security-descriptor-string-format).
- **Restrict a directory so new children inherit only that ACE:**
  `icacls "<dir>" /inheritance:r /grant:r "*<SID>:(OI)(CI)F" /Q` ⇒ a file created inside later shows `DOMAIN\user:(I)(F)` only; SDDL `D:AI(A;ID;FA;;;S-1-12-1-…)`; the usual `tmp` + `rename` replace works inside it [local run].
- `/grant:r` **alone is not enough**: [local run] with `*SID:(R,W)` and no `/inheritance:r` the file kept `SYSTEM`, `Administrators` and the user's inherited `(I)(F)` ACEs (SDDL `D:AI(A;;0x12019f;;;<SID>)(A;ID;FA;;;SY)(A;ID;FA;;;BA)(A;ID;FA;;;<SID>)`), and `/inheritance:r` in a later call fixed it. Doing both in **one** invocation worked. After `/inheritance:r`, SYSTEM and Administrators lose the file: backup/AV running as SYSTEM can no longer read it, and an admin can only get in by taking ownership (*Analysis (not from a source)*; the owner can always rewrite the DACL).
- **Getting the SID safely:** run `%SystemRoot%\System32\whoami.exe /user /fo csv /nh` by absolute path with `execFile` (no shell) and parse `^"[^"]+","(S-1-\d+(-\d+)+)"$`. [local run] on this machine: `"domain\user","S-1-12-1-…"` (name, domain and SID redacted): a **Microsoft Entra ID** account (`S-1-12-1-…`), where friendly-name resolution (`USERDOMAIN\USERNAME` from env vars, or `os.userInfo().username`, which has no domain) is the fragile route; the numeric SID with the `*` prefix always works. `[Security.Principal.WindowsIdentity]::GetCurrent().User.Value` returned the same SID.
- **Verify from the SDDL, not from names:** `icacls "<file>" /save "<tmp>" /Q` writes `<name>` + the SDDL line, as **UTF-16LE** text, to `<tmp>` (my parser decoded it with `toString('utf16le')` and stripped a leading U+FEFF if present; I did not inspect the raw bytes for a BOM) (non-secret; delete it). Parse `D:…(type;flags;rights;;;sid)…`; accept iff every ACE is `A` (allow) for the current SID and there is no other ACE. (Do not require the `P` flag: a file born in a restricted directory has `D:AI(A;ID;FA;;;<SID>)`.) Printing `icacls "<file>"` also works for humans but prints account names.

**2.4 The create-then-restrict race, and three ways to close it** (all three [local run])
| Way | Windows result | Cost |
|---|---|---|
| (a) **Restricted directory**: `ensurePrivateDir` once (`mkdir`, then `icacls … (OI)(CI)F`, verify); create files inside with `open(p,'wx')` | file born with a single inherited ACE (`D:AI(A;ID;FA;;;<SID>)`); no window | one `icacls` per directory |
| (b) **Empty file first**: `open(tmp,'wx')` (empty) → `icacls` → verify → write secret → `rename` | the secret is only ever written after the ACL is verified; works even with the handle already open (my `writePrivateFile`) | ~65 ms `icacls` + ~65 ms verify |
| (c) **Atomic DACL at creation**: PowerShell 5.1 `New-Object System.IO.FileStream($path, CreateNew, FullControl, None, 4096, None, $fileSecurity)` with `FileSecurity.SetAccessRuleProtection($true,$false)` + one Allow rule for `WindowsIdentity.GetCurrent().User` (constructor `FileStream(String, FileMode, FileSystemRights, FileShare, Int32, FileOptions, FileSecurity)`: https://learn.microsoft.com/en-us/dotnet/api/system.io.filestream.-ctor) | born `D:P(A;;FA;;;<SID>)`; `CreateNew` on an existing path fails closed | ~0.5 s per file (PowerShell start-up) |
On POSIX there is **no window**: `open(…,'wx',0o600)` creates the inode with that mode. For an **existing** file `writeFile(…, {mode})` does nothing about its mode: use `fh.chmod(0o600)` (fchmod) or, better, write a new file and `rename` it over the old one (the new inode has the right mode and ownership).

**2.5 Tested helper** (*Analysis (not from a source)*; **[local run]** 3 `node --test` cases pass on Node 24.19.0 under Windows: content + replace + owner-only verified by SDDL, `ensurePrivateDir` idempotent and files born restricted, no `.tmp` leftovers; the POSIX branch was written from the docs above and is **not executed** here):
```ts
export async function writePrivateFile(path: string, data: string | Uint8Array): Promise<void> {
  const tmp = `${path}.${process.pid}.${randomBytes(4).toString('hex')}.tmp`;
  if (process.platform !== 'win32') {
    const fh = await open(tmp, 'wx', 0o600);          // atomic create with 0600 & ~umask; fails on existing path/symlink
    try { await fh.writeFile(data); await fh.sync(); if (((await fh.stat()).mode & 0o077) !== 0) throw new Error('unexpected file mode'); } finally { await fh.close(); }
  } else {
    const fh = await open(tmp, 'wx');                  // empty file with the parent's ACL: nothing secret in it yet
    try {
      await restrictToCurrentUser(tmp);                // icacls <tmp> /inheritance:r /grant:r *<SID>:F /Q   (absolute path to icacls.exe, execFile, no shell)
      if (!(await isCurrentUserOnly(tmp))) throw new Error('ACL verification failed');   // icacls /save → SDDL → single Allow ACE for our SID
      await fh.writeFile(data); await fh.sync();       // secret written only after verification
    } finally { await fh.close(); }
  }
  await rename(tmp, path);                             // replaces atomically, keeps the restricted ACL / 0600
}
```
`ensurePrivateDir(dir)`: `mkdir(dir, { recursive: true, mode: 0o700 })`; POSIX then `lstat` and require directory + `uid === process.getuid()` + `(mode & 0o077) === 0`; Windows restricts with `(OI)(CI)F` when it created the directory (or when verification fails) and re-verifies. Never restrict a directory you did not create (`%USERPROFILE%`, `C:\Users\Public`…).

## 3. Node's permission model (`--permission`) for a child that decodes untrusted images

- Normalisation worked as intended [local run]: `..` segments resolving to the granted file were allowed, `..` escapes denied; `\\?\C:\…` allowed for the granted file and denied for an ungranted one; an **8.3 short path** and **forward-slash** spelling of an ungranted file were denied; paths with spaces and non-ASCII characters work when passed as separate `argv` elements (no quoting).
- Wildcard: "After passing a wildcard character (`*`) all subsequent characters will be ignored" `[N24 permissions.md#L242-L243]` and `--allow-fs-read=/home/test*` matches everything with that prefix `[N24 permissions.md#L239-L240]`. *Analysis (not from a source):* a photo named `a*b.jpg` on macOS/Linux would turn the grant into `a*`; reject or copy-rename input paths containing `*` (Windows forbids `*` in names).
- With only the file grants, `readdir(outDir)` was denied (no read grant) while create/`mkdir -p`/write succeeded; `copyFile(input, out/…)` worked; `rename`/`unlink` of the input were denied.
- The entry script: implicit read from 22.17/24.2 [local run on 24.19.0 and 22.23.5: worked without an explicit grant]; **grant it explicitly anyway** (harmless, and required on 22.13-22.16 which the repo's `engines` allows). Any module the entry `import`s needs its own read grant [local run: sibling `helper.mjs` ⇒ `ERR_ACCESS_DENIED` until its folder was granted]: **bundle the decoder into one file**.

**3.4 Runtime check:** `process.permission` exists only when the model is on, so guard it: `process.permission?.has('fs.write', outDir)`. In the child, assert the policy at start-up and exit non-zero if it is looser than expected, e.g. `has('fs.read') === false && has('fs.write') === false && has('child') === false && has('worker') === false && has('fs.read', input) && has('fs.write', join(outDir, 'x'))` (all `true`/`false` as listed; [local run] the `has()` table was identical on all four versions for these scopes).

**3.5 Spawning the restricted decoder** (tested shape: `parent.mjs`/`decoder.mjs`; 4 policy variants run per Node version)
```ts
import { spawn } from 'node:child_process';
export function spawnDecoder(o: { nodeBin: string; entry: string; input: string; outDir: string; timeoutMs?: number }) {
  if (/[*]/.test(o.input) || /[*]/.test(o.outDir)) throw new Error('refusing a path containing "*" (wildcard in the permission grant)');
  const args = [
    '--permission',
    `--allow-fs-read=${o.input}`,          // exactly one file (exact match)
    `--allow-fs-read=${o.entry}`,          // the single bundled decoder file (implicit on >=22.17/24.2, explicit = portable)
    `--allow-fs-write=${o.outDir}`,         // one EXISTING folder (recursive)
    '--max-old-space-size=512',
    o.entry, o.input, o.outDir,
  ];
  return spawn(o.nodeBin, args, {
    shell: false, windowsHide: true, stdio: ['ignore', 'pipe', 'pipe'],         // no extra fds: stdio fds bypass the model
    signal: AbortSignal.timeout(o.timeoutMs ?? 30_000),
    env: { SystemRoot: process.env.SystemRoot ?? '' },                          // tested shape; never forward API keys or NODE_OPTIONS
  });
}
```
  Observations from the runs: [local run] the child's `process.env` on Windows still contained system variables (`HOMEDRIVE, HOMEPATH, LOGONSERVER, PATH, SYSTEMDRIVE, TEMP, USERDOMAIN, USERNAME, USERPROFILE, WINDIR`) although only `SystemRoot` and one custom variable were passed, so treat `env` as "do not forward secrets", not as hiding the user name. Start-up cost is unchanged by the model (avg 139 ms with `--permission` vs 151 ms without, 10 runs each, Node 24.19.0 / Windows). If a flag is only valid on newer Node (`--allow-net` ≥ 25, `--permission-audit` ≥ 24.20), **gate by the child binary's version**: passing an unknown flag is a hard start-up error (`bad option`).
  - Result channel: the child writes derivative files into `outDir` and a small JSON on stdout; the parent re-validates the output (size, magic bytes) because the child is untrusted.
  - **What this does not give you:** network isolation on Node 22/24 (use an OS facility if exfiltration matters: *Analysis (not from a source)*: Windows Firewall per-program rule, Linux `unshare -n`/seccomp, macOS App Sandbox, none of which I tested), memory/CPU quotas, or protection against a decoder that is itself malicious code. Do not give the child a SQLite handle or an open fd to anything sensitive.

**5.4 SPDX licence-expression rules that matter for an allow-list** (SPDX 2.3 Annex D `[SPDX23 SPDX-license-expressions.md#L44-L54]`; the current spec `[SPDX3 #L13-L63]`; licence list data https://spdx.org/licenses/licenses.json)
- **Grammar:** `simple-expression = license-id / license-id"+" / license-ref`; `compound = simple / simple WITH exception-id / compound AND compound / compound OR compound / "(" compound ")"`; `license-ref = ["DocumentRef-"idstring":"]"LicenseRef-"idstring`; `idstring = 1*(ALPHA / DIGIT / "-" / ".")` `[SPDX3 #L13-L39]`. Also valid: `exception-id` from the exceptions list (e.g. `LLVM-exception`, `Classpath-exception-2.0`; 86 entries in list 3.29.0) or a user-defined `AdditionRef-…` (new in the current spec, not in 2.3).
- **Whitespace:** none between an id and its `+`; whitespace on both sides of `WITH`; whitespace and/or parentheses around `AND`/`OR` `[SPDX23 #L44]`.
- **Case:** operators are matched **case-sensitively**: 2.3 = upper case only (`AND`, `OR`, `WITH`) `[SPDX23 #L50]`; the current spec also accepts all-lower-case `and`/`or`/`with` `[SPDX3 #L55]`. Licence and exception **ids are case-insensitive** (`MIT` = `mit`) but the canonical case should be kept; the `LicenseRef-` prefix itself is case-sensitive (`licenseref-name` is invalid) `[SPDX3 #L57-L61]`. [local run] `spdx-expression-parse` 5.0.0 **rejects** `mit` and `MIT or Apache-2.0`, so normalise before parsing if you want to be lenient.
- **Precedence** (tightest first): `+`, `WITH`, `AND`, `OR`; so `LGPL-2.1-only OR BSD-3-Clause AND MIT` = `LGPL-2.1-only OR (BSD-3-Clause AND MIT)`; parentheses override `[SPDX3 #L165-L192]`.
- **`LicenseRef-*`**: a document-local reference that carries its text elsewhere: never auto-allowed; an allow-list can only match it by an explicit per-package override. **Deprecated ids**: SPDX list 3.29.0 (released 2026-09-16) has 740 ids, **32 deprecated** (`isDeprecatedLicenseId`), e.g. `GPL-2.0`, `GPL-3.0`, `GPL-2.0+`, `LGPL-2.1+`, `GPL-2.0-with-bison-exception`, `BSD-2-Clause-FreeBSD`, `wxWindows`, `Nunit`; the successors are the `-only`/`-or-later` forms. The repo's eight allowed ids (`MIT, ISC, BSD-2-Clause, BSD-3-Clause, Apache-2.0, 0BSD, BlueOak-1.0.0, CC0-1.0`) are all current (checked against list 3.29.0). npm's `license` field accepts `UNLICENSED` and `SEE LICENSE IN <file>` which are **not** SPDX expressions (the parser rejects them).
- **Test of the repo's current checker** (`scripts/check-licenses.mjs:33-38`: strips parentheses, splits on `AND` first, then on `OR`): [local run] vs `spdx-satisfies` 6.0.1 on 25 expressions. **No false positive.** False negatives (stricter than the spec): `GPL-3.0-only AND MIT OR Apache-2.0`, `Apache-2.0 OR (GPL-3.0-only AND LGPL-2.1-only)`, `MIT OR GPL-3.0-only AND LGPL-2.1-only` (all really satisfied via `Apache-2.0`/`MIT`), and `Apache-2.0+`; `WITH` forms, `LicenseRef-*`, `Unlicense`, `GPL-2.0(+)` are false in both; lower-case or non-SPDX strings (`mit`, `MIT/X11`, `BSD`, `SEE LICENSE IN…`, `UNLICENSED`) are false (fail closed). It is safe but coarse.
- **Libraries** (npm registry metadata + installed `package.json`): `spdx-expression-parse@5.0.0` (MIT; published 2026-07-16; deps `spdx-exceptions` **CC-BY-3.0**, `spdx-license-ids` CC0-1.0), `spdx-satisfies@6.0.1` (MIT; 2026-11-07; deps `spdx-compare` MIT, `spdx-ranges` **`(MIT AND CC-BY-3.0)`**), `spdx-correct@4.0.0` (Apache-2.0; 2026-11-17). **6.2 API, exact calls** (README `[SSH2 README.md#L945-L985]`, `[SSH2 SFTP.md#L226-L283]`; the flows below ran [local run] on Node 24.19.0)
```js
const { Client, utils } = require('ssh2');                      // SFTP constants: utils.sftp.{OPEN_MODE, STATUS_CODE}  (README's server example destructures `sftp` from the module root; in 1.17.0 it is utils.sftp)
const conn = new Client();
conn.on('ready', () => conn.sftp((err, sftp) => {
  sftp.fastPut(localPath, remotePath, { concurrency: 64, chunkSize: 32768,   // defaults; "parallel reads"
    step: (totalTransferred, chunk, total) => progress(totalTransferred, total),
    mode: 0o644 }, (err) => { /* err is falsy on success */ conn.end(); });
})).on('error', (e) => { /* e.level: 'handshake' | 'client-authentication' | 'client-timeout' | … */ })
  .connect({ host, port: 22, username,
    privateKey: fs.readFileSync(keyPath), passphrase,                  // OpenSSH, RFC4716 or PPK; passphrase only for encrypted keys
    readyTimeout: 20_000,                                              // default 20000
    keepaliveInterval: 15_000, keepaliveCountMax: 3,                   // defaults 0 (off) and 3
    hostVerifier: (key /* raw wire-format Buffer */, cb) => cb(pinOk(key)) });
```
- **`fastPut` options:** `concurrency` (default 64), `chunkSize` (default 32768), `step(total_transferred, chunk, total)`, `mode`; callback has one argument (`err`) `[SSH2 SFTP.md#L236-L246]`. [local run] an 8 MiB + 123 B file produced **257 `step` calls** (one per 32 KiB chunk plus the 123-byte tail; last `{done: 8388731, chunk: 123, total: 8388731}`), the remote copy's SHA-256 matched, 0.24 s against the in-process server (~33 MiB/s; loopback figure only, not a network benchmark). `sftp.createWriteStream(path, {flags:'w', mode:0o666, autoClose:true, start?})` is the streaming alternative (back-pressure, no parallelism) `[SSH2 SFTP.md#L269-L280]`.
- **Resume** (there is no resume option): `const { size } = await stat(remote)`; `fs.createReadStream(local, { start: size })` piped into `sftp.createWriteStream(remote, { flags: 'r+', start: size })`. "Modifying a file rather than replacing it may require a flags mode of 'r+' rather than the default mode 'w'" `[SSH2 SFTP.md#L280]`. [local run] the server saw OPEN mode `'r+'` (READ|WRITE, bits 3: **no `TRUNC`**) for the resume and `'w'` (bits 26 = WRITE|CREAT|TRUNC) for the default, and a 3,000,000-byte partial file was completed to 8,388,731 bytes with a matching SHA-256. *Analysis:* verify what is already there before appending (compare a SHA-256 of the first N bytes through `createReadStream(remote, {start:0, end:N-1})` or upload to `name.part` and `rename` at the end: `sftp.rename` exists) and fall back to a full restart on mismatch.
- **Progress for streams:** count bytes in the read stream's `data` events; `fastPut` has `step`.
- **Keepalive** `[SSH2 README.md#L957-L959]`: `keepaliveInterval` ms (default 0 = off), `keepaliveCountMax` (default 3, "similar to OpenSSH's ServerAliveCountMax"). Implementation: after `countMax` unanswered pings the client emits `Error('Keepalive timeout')` with `level = 'client-timeout'` and destroys the socket `[SSH2 lib/client.js#L710-L735]`. [local run] with 200 ms × `countMax: 2` through a proxy that swallowed all traffic after login: `Keepalive timeout`, `level: client-timeout` after **609 ms** (≈ interval × (countMax + 1)).
- **Errors seen** [local run]: bad password: `All configured authentication methods failed`, `level: client-authentication`; wrong key passphrase: `Cannot parse privateKey: OpenSSH key integrity check failed -- bad passphrase?`; missing passphrase: `Cannot parse privateKey: Encrypted private OpenSSH key detected, but no passphrase given`; decrypting an Ed25519 key with the pure-JS bcrypt KDF took **~410-480 ms** (parse once, reuse: `utils.parseKey(buf, passphrase)` returns a key object or an `Error`).

**6.3 Host-key verification and pinning** (README `[SSH2 README.md#L953-L955]`; [local run] against an OpenSSH-generated ed25519 host key)
- `hostVerifier(key[, callback])`: `key` is the **raw wire-format host key `Buffer`** (51 bytes for ed25519: `uint32 len | "ssh-ed25519" | uint32 len | 32-byte key`); return `true`/`false`, **or** call `callback(true|false)` for async checks (works [local run]). `utils.parseKey(key).type` gives `ssh-ed25519`, `ssh-rsa`, `ecdsa-sha2-nistp256`… **If `hostVerifier` is not set, the key is auto-accepted** (README default) [local run: connected to an unknown key with no verifier]. A `false` result ends the connection with `Error: Host denied (verification failed)`, `level: handshake` [local run].
- `hostHash: 'sha256'` passes the verifier a **64-character lowercase hex string**, *not* the base64 form OpenSSH prints [local run]; convert with `Buffer.from(hex,'hex').toString('base64').replace(/=+$/,'')`. Simplest is to leave `hostHash` unset and hash the raw `Buffer` yourself.
- **OpenSSH-compatible fingerprint** [local run, exact match with `ssh-keygen -lf host.pub` = `256 SHA256:1uiHuV04Fvirae8EZndhsJ5NIS4rrXiqAm4fhRXDQQ4 host (ED25519)`]: `'SHA256:' + createHash('sha256').update(key).digest('base64').replace(/=+$/, '')`. A legacy MD5 form `MD5:aa:bb:…` is what old `ssh-keygen -E md5` prints; avoid.
- **Pinning design** (*Analysis; the verifier flow ran, the file store did not*): store `{ host:port → [{alg, sha256}] }` in a private file (Topic 2); on first contact show the fingerprint and require explicit confirmation (TOFU) or pre-provision it (best for a studio's own server); on mismatch **fail closed** with a message that shows both fingerprints; allow several pins for key rotation. To honour an existing `~/.ssh/known_hosts`: `ssh2` has **no parser**; lines are `[markers] hostnames keytype base64key`, hostnames comma-separated, non-default ports written `[host]:port`, hashed names start with `|` and only one hashed name may appear per line `[sshd(8) "SSH_KNOWN_HOSTS FILE FORMAT"] https://man.openbsd.org/sshd.8` (the `|1|salt|hash` HMAC-SHA-1 construction is from `ssh-keygen(1) -H`: **UNVERIFIED**, not read here); compare `Buffer.from(base64key,'base64')` to the `key` passed to the verifier byte-for-byte.

**6.4 Private keys** `[SSH2 README.md#L969-L975]`: `privateKey` accepts OpenSSH-format keys (Ed25519/ECDSA/RSA; encrypted ones need `passphrase`); [local run] an Ed25519 key encrypted by `ssh-keygen -N "correct horse"` authenticated against the in-process server (publickey, signature verified server-side with `parsedPub.verify(ctx.blob, ctx.signature, ctx.hashAlgo)`). For an ssh-agent use the `agent` option (not exercised here: **UNVERIFIED** on Windows named pipes). Keys can be generated in-process: `utils.generateKeyPairSync('ed25519')` (+ `'ecdsa'`, `'rsa'`) `[SSH2 README.md#L680-L687]`.

**6.5 Testing without a network: ssh2's own `Server` in-process** (ran [local run]; 8 MiB upload, resume, pin match/mismatch, passphrase, keepalive all passed). Server side (condensed from the README's SFTP-only server `[SSH2 README.md#L566-L673]`, extended to store bytes):
```js
const { Server, utils } = require('ssh2'); const { OPEN_MODE, STATUS_CODE } = utils.sftp;
const files = new Map();                                              // path -> { buf, len }
const server = new Server({ hostKeys: [fs.readFileSync('host')] }, (client) => {
  client.on('authentication', (ctx) => (ctx.method === 'password' && ctx.username === 'u' && ctx.password === 'pw') ? ctx.accept() : ctx.reject(['password']))
        .on('ready', () => client.on('session', (accept) => accept().on('sftp', (accept) => {
    const sftp = accept(), handles = new Map(); let n = 0;
    const attrs = (f) => ({ mode: 0o100644, uid: 0, gid: 0, size: f.len, atime: 0, mtime: 0 });
    sftp.on('REALPATH', (id, p) => sftp.name(id, [{ filename: p === '.' ? '/upload' : p, longname: p, attrs: {} }]))
        .on('OPEN', (id, name, flags) => { let f = files.get(name);
          if (!f) { if (!(flags & OPEN_MODE.CREAT)) return sftp.status(id, STATUS_CODE.NO_SUCH_FILE); f = { buf: Buffer.alloc(1 << 20), len: 0 }; files.set(name, f); }
          if (flags & OPEN_MODE.TRUNC) f.len = 0;
          const h = Buffer.alloc(4); h.writeUInt32BE(n); handles.set(n++, f); sftp.handle(id, h); })
        .on('WRITE', (id, h, off, data) => { const f = handles.get(h.readUInt32BE(0)); const end = off + data.length;
          if (end > f.buf.length) { const nb = Buffer.alloc(Math.max(end, f.buf.length * 2)); f.buf.copy(nb, 0, 0, f.len); f.buf = nb; }
          data.copy(f.buf, off); f.len = Math.max(f.len, end); sftp.status(id, STATUS_CODE.OK); })
        .on('READ', (id, h, off, len) => { const f = handles.get(h.readUInt32BE(0)); off >= f.len ? sftp.status(id, STATUS_CODE.EOF) : sftp.data(id, f.buf.subarray(off, Math.min(off + len, f.len))); })
        .on('FSTAT', (id, h) => sftp.attrs(id, attrs(handles.get(h.readUInt32BE(0)))))
        .on('STAT', (id, p) => files.has(p) ? sftp.attrs(id, attrs(files.get(p))) : sftp.status(id, STATUS_CODE.NO_SUCH_FILE))
        .on('LSTAT', (id, p) => files.has(p) ? sftp.attrs(id, attrs(files.get(p))) : sftp.status(id, STATUS_CODE.NO_SUCH_FILE))
        .on('SETSTAT', (id) => sftp.status(id, STATUS_CODE.OK)).on('FSETSTAT', (id) => sftp.status(id, STATUS_CODE.OK))
        .on('RENAME', (id, a, b) => { files.set(b, files.get(a)); files.delete(a); sftp.status(id, STATUS_CODE.OK); })
        .on('CLOSE', (id, h) => { handles.delete(h.readUInt32BE(0)); sftp.status(id, STATUS_CODE.OK); });
  })));
}).listen(0, '127.0.0.1');
```
Client: `new Client().connect({ host: '127.0.0.1', port: server.address().port, username: 'u', password: 'pw', hostVerifier: (k) => sha256fp(k) === pinned })`. Generate the host key once with `ssh-keygen -t ed25519 -N "" -f host` (or `utils.generateKeyPairSync('ed25519').private`). For the keepalive test put a TCP proxy between client and server and stop forwarding after `ready`. **Test matrix that should live in CI:** (1) pinned fingerprint accepted, (2) one wrong byte rejected with `Host denied`, (3) no-verifier path is **not reachable** from our code, (4) 8 MiB upload SHA-256 equal and `step` monotonic, (5) resume from a partial file equals full upload and a corrupted partial is detected, (6) encrypted key: good/bad/no passphrase, (7) keepalive timeout surfaces as `client-timeout`, (8) server closes mid-transfer ⇒ retry with resume.

## 8. Accessibility and i18n for a keyboard-driven photo review grid (plain HTML page)

### Answer

**Summary.** A thumbnail wall is a **layout grid** in WAI-ARIA terms: `role="grid"` > `role="row"` > `role="gridcell"`, **one tab stop for the whole grid**, arrow-key navigation, `aria-selected` for picks. The WCAG 2.2 AA criteria that actually constrain such a UI are 2.1.4 (single-key shortcuts), 2.4.7/2.4.11 (visible, not-obscured focus), 2.5.7 (no drag-only actions), 2.5.8 (24×24 CSS px targets), 1.4.3/1.4.11 (contrast) and 4.1.3 (status messages). For i18n: neither Node 22, 24 nor 26 has `Intl.MessageFormat` (it is a TC39 Stage 1 proposal), so ship ICU message strings with **`intl-messageformat`** (BSD-3-Clause, 33.8 KB minified); Hindi needs its own plural rule (**0 and 1 are both `one`**, and so is 0.5) and Indian digit grouping (`1,00,000`) which `Intl` already provides with Latin digits by default.

**8.1 Grid pattern** (APG: https://www.w3.org/WAI/ARIA/apg/patterns/grid/; ARIA 1.2: https://www.w3.org/TR/wai-aria-1.2/; retrieved 2026-11-22; `L…` numbers in this section and in 8.2 are line numbers of my plain-text conversion of the retrieved page, for orientation, not stable anchors)
- **Which pattern.** "Uses of the grid pattern broadly fall into two categories: presenting tabular information (data grids) and grouping other widgets (layout grids)"; "using the grid role on an element does not necessarily imply that its visual presentation is tabular"; a grid is a composite widget: "Only one of the focusable elements contained by the grid is included in the page tab sequence" `[APG grid page L26-L34]`. A **layout grid** "can be used to group a set of interactive elements, such as links, buttons, or checkboxes… only one element in the entire grid is included in the tab sequence, grouping with a grid can dramatically reduce the number of tab stops" (L88-L89), which suits 1,500 thumbnails. ARIA 1.2 definition: "A composite widget containing a collection of one or more rows with one or more cells where some or all cells in the grid are focusable by using methods of two-dimensional navigation, such as directional arrow keys" (`wai-aria-1.2 L808`).
- **Role structure** (APG L188-L206; ARIA 1.2 `grid`: required owned elements `row` or `rowgroup → row`, supported `aria-multiselectable`, `aria-readonly`, inherited `aria-activedescendant`, `aria-colcount`, `aria-rowcount`: `wai-aria-1.2 L2098-L2109`): grid container `role="grid"` with an accessible name (`aria-labelledby`, else `aria-label`; optional `aria-describedby`); each row `role="row"`; each thumbnail cell `role="gridcell"` (no header cells needed); a selected cell has `aria-selected="true"` (`aria-selected`: `wai-aria-1.2 L5370`) and the grid `aria-multiselectable="true"`; if rows are virtualised or not all in the DOM, set `aria-rowcount`/`aria-colcount` on the grid and `aria-rowindex`/`aria-colindex` on rows/cells. If you build the grid from a `<table>`, the implied roles apply (L211-L213).
- **What gets focus** (APG L150-L158): "There are two optimal cell design and focus behavior combinations": (1) a cell with one widget whose operation does not need arrow keys (link, button, checkbox…) and grid navigation focuses **that widget**; (2) a cell with **text or a single graphic** and navigation focuses **the cell**. A thumbnail with a caption fits (2): focus the cell and give it an accessible name that carries the state (`aria-label="IMG_0042, 3 stars, rejected"` or `aria-labelledby` → the visible caption). If a cell has several controls (rating, flag, compare), use APG's Enter/F2 convention to enter/leave the cell (L159-L186) instead of extra tab stops.
- **Keyboard interactions for a layout grid** (APG L102-L145): **Right/Left/Down/Up Arrow** move one cell (at an edge focus does not move; wrapping to the next row/column is *optional* for layout grids, and APG says such wrapping "can be very helpful in a layout grid" but "would be disorienting if used in a data grid", L98); **Page Down/Up** move "an author-determined number of rows"; **Home/End** = first/last cell **in the row** (L121-L124); **Ctrl+Home/Ctrl+End** = first cell of first row / last cell of last row; if navigation can add rows dynamically, Ctrl+End "may move focus to the last row in the DOM rather than the last available row in the back-end data" (L132). Selection keys "commonly used": **Ctrl+Space** selects the column, **Shift+Space** selects the row, **Ctrl+A** selects all, **Shift+Arrow** extends the selection (L135-L142); APG notes it would be unusual for a layout grid to need selection, but a culling tool does, so add **Space = toggle selection of the focused cell** (our convention, not APG's) and keep the others.
- **Focus management: roving tabindex vs `aria-activedescendant`** (APG "Developing a Keyboard Interface" https://www.w3.org/WAI/ARIA/apg/practices/keyboard-interface/ L169-L191): roving = `tabindex="0"` on the one active cell, `tabindex="-1"` on all others, move both and call `focus()` on each arrow key; "One benefit of using roving tabindex rather than `aria-activedescendant`… is that the user agent will scroll the newly focused element into view" (L180). `aria-activedescendant` keeps DOM focus on the container, requires the active descendant to exist in the DOM, and assistive technologies "consider the element referred to as active to be the focused element" (L182-L186). **Choose roving tabindex** for the photo grid (and keep exactly one `tabindex="0"`). Also: "The visual focus indicator must always be visible. The selected state must be visually distinct from the focus indicator" (L113-L114) and focus ≠ selection (L98-L101).
- **Tested controller** (*Analysis; logic executed [local run] under jsdom 31.0.1, no browser/screen reader*): 15 `assert` statements passed on a 5-column grid with a ragged last row (3 cells): one tab stop; arrows move by cell and do not wrap; ArrowDown keeps the column; Home/End by row; PageDown by `pageRows`; Ctrl+Home/End; Shift+Arrow extends `aria-selected`; Space toggles and writes "IMG_0006 not selected. 1 selected" into a `role="status"` node; a single-letter shortcut (`p`) fires only while the grid has focus and not at all when the setting is off. Core of it:
```js
const rows = () => [...grid.querySelectorAll('[role="row"]')].map((r) => [...r.querySelectorAll('[role="gridcell"]')]);
for (const c of cells()) c.tabIndex = c === current ? 0 : -1;                    // roving tabindex: exactly one tab stop in the grid
const focusCell = (c) => { current.tabIndex = -1; c.tabIndex = 0; current = c; c.focus(); };
grid.addEventListener('focusin', …);                                              // keep `current` in sync when a pointer click focuses a cell
grid.addEventListener('keydown', (e) => { /* ArrowLeft/Right/Up/Down, PageUp/Down(pageRows), Home/End (Ctrl = grid), ' ' toggles aria-selected, Shift+Arrow extends */ });
```
  Not covered by the test (needs a real browser/AT): scroll-into-view with a sticky header, screen-reader announcements, high-DPI hit targets, virtualisation, Hindi/RTL text.

**8.3 i18n: ICU MessageFormat, libraries, Hindi**
- **Syntax** (ICU user guide https://unicode-org.github.io/icu/userguide/format_parse/messages/, L149-L175): `{n, plural, =0 {…} one {# photo} other {# photos}}`, `select`, `selectordinal`, `offset:1`; the guide recommends complex arguments be "the outermost structure of a message" with **full sentences in the sub-messages**, and "place the select arguments… on the outside and nest the plural arguments". [local run] with `intl-messageformat` 12.2.0: `other` is **mandatory** (`MISSING_OTHER_CLAUSE`); `#` prints the locale-formatted number (`1,500` in en, `1,00,000` in hi-IN); an exact `=0` branch wins over the plural category; `select` needs `other`; `{n, selectordinal, one {#st} two {#nd} few {#rd} other {#th}}` gave `1st 2nd 3rd 4th 11th 22nd`; apostrophe quoting works as in ICU (`It''s '{'literal'}'` → `It's {literal}`); `{n, number}` → `1,23,456` and `{n, number, ::compact-short}` → `1.2 लाख` in `hi-IN`; rich-text tags `<b>{name}</b>` are mapped through a callback (no raw HTML injection).
- **`Intl.MessageFormat` does not exist**: [local run] `typeof Intl.MessageFormat` is `'undefined'` on Node 22.23.5, 24.19.0, 24.22.3 and 26.13.1; `Intl` has `DateTimeFormat, NumberFormat, Collator, PluralRules, RelativeTimeFormat, ListFormat, Locale, DisplayNames, Segmenter` and (24+) `DurationFormat` (**not on 22.23.5**). The TC39 proposal is **Stage 1** (champions Eemeli Aro, Ujjwal Sharma; updates through 2024 February on its page: https://github.com/tc39/proposal-intl-messageformat). The successor syntax, **Unicode MessageFormat 2 (MF2)**, is UTS #35 Part 9, dated 2026-10-21 and "a stable document" (https://unicode.org/reports/tr35/tr35-messageFormat.html).
- **Library comparison** (npm registry metadata + [local run] with esbuild 0.28.2 `--bundle --minify --platform=node`, a hello-world plural message each; all ran and printed `1 photo`):
| Library | Syntax | Licence | Deps | Minified / gzip | Published |
|---|---|---|---|---|---|
| **`intl-messageformat` 12.2.0** (+ `@formatjs/icu-messageformat-parser` 3.5.23 MIT, `@formatjs/fast-memoize` 3.1.7 MIT, `@formatjs/icu-skeleton-parser`) | ICU MessageFormat v1 | **BSD-3-Clause** (all deps MIT): all on the repo's `ALLOWED` list | 2 direct | **33,774 B / 9,889 B** | 2026-11-17 |

  *Analysis:* the plan says "ICU message format" (`ARCHITECTURE_AND_PLAN.md:611`), so **`intl-messageformat`** is the lightest ICU-syntax option whose whole tree is already licence-compatible; its plural selection calls the platform's `Intl.PluralRules` (`select(numericValue - offset)`, `node_modules/intl-messageformat/index.js:140-144` of 12.2.0; it throws if `Intl.PluralRules` is missing), so it uses the engine's CLDR (CLDR 48 on all three LTS lines [local run]) and cannot drift from it. MF2 (`messageformat`) is lighter still but is a different syntax/ecosystem (translator tooling is still ICU-centric). In the browser page the same library bundles with the page script (the review UI is plain HTML/JS: `ARCHITECTURE_AND_PLAN.md:699`).
- **CLDR plural categories** (CLDR tag `release-48`, commit `acd6d88ae493633240e19a87a721076a8a75c310`, `common/supplemental/plurals.xml`; Node 24.19.0 reports CLDR 48.0): **English** (`L30-L33`, shared with de, nl, sv…): `one` = `i = 1 and v = 0` (integer sample `1`); everything else `other` (0, 2, 1.5, and "1.0" with a visible fraction). **Hindi** (`L22-L25`, shared with bn, gu, kn, zu…): **`one` = `i = 0 or n = 1`** (integer samples 0, 1; decimals 0.0~1.0, 0.00~0.04); `other` = 2~17, 100, 1000, 100000…, 1.1~2.6. Operands: `n` absolute value, `i` integer digits, `v` visible fraction digits. [local run, `Intl.PluralRules`] **en:** 0→`other`, 1→`one`, 2→`other`, 0.5→`other`, 1.5→`other`; **hi:** **0→`one`, 1→`one`, 0.5→`one`**, 1.5→`other`, 2→`other`, 21→`other`; with `minimumFractionDigits: 1` the value `1.0` is `other` in en (v=1) but `one` in hi. So (a) Hindi has **no `zero` category: write `=0` explicitly** (`=0 {कोई फ़ोटो नहीं} one {# फ़ोटो} other {# फ़ोटो}` printed `कोई फ़ोटो नहीं | 1 फ़ोटो | 0.5 फ़ोटो`), (b) never hard-code `n === 1`, (c) ordinals differ: en `one/two/few/other`; hi `one` (1), `two` (2, 3), `few` (4), `many` (6), `other` (`ordinals.xml L143-L149`).
- **`Intl` on Node 24 (full ICU)** [local run]: Node's docs: "The full ICU data set is provided by Node.js by default" and `--with-intl=full-icu` is the default (`[N24 intl.md#L28]`, `[N24 intl.md#L42]`); `process.config.variables.icu_small === false`, ICU 78.3 / CLDR 48.0 / Unicode 17.0 on 22.23.5, 24.19.0, 24.22.3 and 26.13.1. `Intl.DateTimeFormat.supportedLocalesOf(['hi','hi-IN','en-IN','ar','he','ta'])` returns all six. **`Intl.NumberFormat('hi-IN')`**: 999 → `999`, 1234.5 → `1,234.5`, **100000 → `1,00,000`**, 1234567.891 → `12,34,567.891` (3;2 grouping), digits are **Latin** (`resolvedOptions().numberingSystem` = `latn` for both `hi` and `hi-IN`); Devanagari digits only with the extension `hi-IN-u-nu-deva` (`१,००,०००`); `en-IN` groups the same way (`1,00,000`) while `en-US` gives `100,000`; INR currency `₹12,34,567.50`; compact `hi-IN`: 1500 → `1.5 हज़ार`, 100000 → `1 लाख`, 12,345,678 → `1.2 क॰`, vs `en-IN` `1.5K`/`1L`/`1.2Cr`. **`Intl.ListFormat('hi')`** → `Haldi, Sangeet, और Wedding` (en: `Haldi, Sangeet, and Wedding`; disjunction `A या B`). **`Intl.RelativeTimeFormat('hi', {numeric:'auto'})`**: −1 day → `कल` **and +1 day → `कल`** (the same word for yesterday and tomorrow: use `numeric:'always'` or print the date); 3 hours ago → `3 घंटे पहले`. `Intl.DurationFormat('hi',{style:'short'})` → `1 घं॰, 5 मि॰` (24+). `Intl.Collator('hi')` sorts `अ क ख ग`. `Intl.Segmenter('hi',{granularity:'grapheme'})` counts `नमस्ते` as 3 graphemes (6 code points): truncate captions by grapheme, never by UTF-16 unit.

### Impact on plan
- `ARCHITECTURE_AND_PLAN.md:610-612` (§7i: WCAG 2.2 AA, full keyboard navigation of the review grid, reduced-motion/high-contrast, ICU messages, English + Hindi, keyboard-first shortcuts) and `:754` (shortcuts ◐) are implementable in the existing plain-HTML `packages/review/src/ui.ts` without a framework: restructure the thumbnail list into `role="grid"`/`row`/`gridcell`, add the roving-tabindex controller, a persistent `role="status"` node, `:focus-visible` rings with ≥ 3:1 contrast, `scroll-padding` for the sticky toolbar, 24×24 minimum for every small control, and no drag-only actions.
- **Keyboard shortcuts and WCAG 2.1.4:** make single-key shortcuts (pick/reject/rating) **active only while the grid has focus** (done in the tested controller) and ship a setting to turn them off or remap them; document them in a `?` dialog.
- i18n: add `intl-messageformat` (BSD-3-Clause; allowed by `scripts/check-licenses.mjs`) behind a small `t(key, values)` helper, one JSON catalogue per locale (`en`, `hi`), message strings with full sentences and `plural`/`select` as the outer construct; test every plural message for `en` and `hi` at 0, 1, 2, 0.5, 1.5 and 100000, add a pseudo-locale, and a lint that rejects a plural without `other`. Use `Intl.NumberFormat/ListFormat/DateTimeFormat` for numbers, lists and dates (Indian grouping comes for free with `hi-IN`/`en-IN`), avoid `numeric:'auto'` relative times in Hindi, use `Intl.Segmenter` when truncating. Node 22 lacks `Intl.DurationFormat`: do not rely on it.
- The agent (Node) and the review page both run on the same CLDR 48 data in practice (Node 22/24/26 all report CLDR 48.0; browsers carry their own), so keep tests for plural/number formatting as **data-driven expectations** rather than reading them from the engine.
